# Trigonometric Proof Engine v0.6.0 — Proof Knowledge Handbook

## 1. Release purpose

Version 0.6.0 combines three things:

1. A question-only bank generated from the eleven requested operation templates.
2. A separate proof-solutions corpus containing the checked derivation for every proved question.
3. A corrected theorem-admission system that permits F08, F09 and F10 to be reused for genuinely different goals without permitting circular proofs.

The companion files are `question-bank.md` and `proof-solutions.md`.

## 2. Finite question-bank scope

Each metavariable `a`, `b`, `c`, `d` and `e` is assigned one atom from:

`sin(x)`, `cos(x)`, `tan(x)`, `cot(x)`, `sec(x)`, `csc(x)`, `1`.

The search enumerates every ordered assignment over the requested templates:

1. `a + b = c`
2. `a - b = c`
3. `ab = c`
4. `a/b = c`
5. `ab + c = d`
6. `ab - c = d`
7. `abc = d`
8. `ab/c = d`
9. `ab + cd = e`
10. `ab - cd = e`
11. `ab/cd = e`

This is exhaustive only for that finite alphabet and those templates. It is not an enumeration of every possible trigonometric identity.

## 3. v0.6 theorem-admission rule

A theorem may be used as a premise only when its own proof dependencies have been independently admitted and replayed. The goal-matching guard must distinguish the target theorem itself from a different identity that happens to follow from it.

### 3.1 Direct-goal exclusion

For an open goal that is F08, F09 or F10 (including reversal, angle renaming, algebraic rearrangement and nonzero constant scaling):

- Do not admit that same theorem as a premise.
- Do not admit its transitive descendants if their dependency chain leads back to the open goal.
- For F08, use the independent geometric certificate.
- For F09/F10, derive them from F08 and the relevant quotient/reciprocal definitions.

### 3.2 Reusable-theorem permission

For a different goal, the theorem may be admitted if its dependencies are valid:

- F08 → geometric certificate `G01 → G03 → G04`.
- F09 → F08, F01, F03.
- F10 → F08, F02, F04.
- F11 → F09.
- F12 → F10.

The engine no longer blocks every goal whose residual is a nonconstant algebraic multiple of a theorem residual. Such a goal is a derived identity, and using the established theorem is legitimate. Direct constant-scaled/rearranged forms remain excluded from their own premise set.

If instance matching becomes ambiguous or exceeds its safety bound, the engine fails closed.

## 4. Independent geometric foundation for F08

The certificate route is:

- **G01:** prove the non-trigonometric Euclidean Pythagorean theorem by a square dissection.
- **G03:** use perpendicular Cartesian projections to obtain the squared-distance relation, including signed coordinates and axis cases.
- **G04:** substitute the unit-circle point `(cos(x), sin(x))` with radius `1`.

This proves `sin(x)**2 + cos(x)**2 = 1` without assuming F08, F09 or F10. The certificate is checked relative to `AX.REAL`, `AX.EUCLID`, `AX.AREA` and `D.UNIT`.

## 5. Parameterised identity: the motivating v0.6 example

For real `p`, `q` and `x`:

`(p*cos(x)+q*sin(x))**2 + (p*sin(x)-q*cos(x))**2 = p**2+q**2`

The proof is:

1. Expand both squared linear combinations by distributivity.
2. Cancel the two cross terms `+2*p*q*sin(x)*cos(x)` and `-2*p*q*sin(x)*cos(x)`.
3. Collect parameter factors:

   `(p**2+q**2)*(sin(x)**2+cos(x)**2)`.

4. Apply F08 explicitly:

   `(p**2+q**2)*1 = p**2+q**2`.

The proof certificate must list F08 as a used theorem, and the F08 dependency provenance must expand to `G01 → G03 → G04`.

### 5.1 Algebraic preprocessing

The proof engine includes a narrow preprocessing rule for expressions containing positive integer powers of additive bases. It:

- expands squared sums using distributivity;
- factors by common parameter groups;
- exposes a subexpression matching an established theorem;
- records each algebraic step separately.

This is exact polynomial algebra. It does not call `trigsimp` or silently introduce a trigonometric identity.

### 5.2 Reverse F08 angle binding

A reverse F08 application can match a literal `1` in a term such as `1-sin(x)**2`. Since the matched literal does not itself contain the theorem's angle variable, the engine permits one narrowly constrained contextual binding: exactly one trigonometric argument must be shared between the current expression and the target. If the shared angle is not unique, the engine does not guess.

## 6. F09 and F10 reuse examples

The companion proof file includes three supplementary acceptance cases:

- **SUP-001:** the parameterised orthogonal linear-combination identity, proved using F08.
- **SUP-002:** `(1+tan(x)**2)*cos(x)**2 = sec(x)**2*cos(x)**2`, proved using F09 as a lemma for a different goal.
- **SUP-003:** `(1+cot(x)**2)*sin(x)**2 = csc(x)**2*sin(x)**2`, proved using F10 as a lemma for a different goal.

The engine also proves F09 and F10 themselves from F08 and their audited definitions, never by assuming F09 or F10.

## 7. False near-miss

The originally typed statement

`(p*cos(x)+q*sin(x))**2 + (p*sin(x)-p*cos(x))**2 = p**2+q**2`

is false in general. At `p=1`, `q=0`, `x=0`, the LHS is `2` and the RHS is `1`. It is deliberately excluded from `question-bank.md` and documented as `DISPROVED` in `proof-solutions.md`.

## 9. Trust boundary

The geometric F08 route is a narrow replay checker, not a complete formalisation of Euclidean geometry. Other admitted catalogue rules use explicit symbolic rewrite steps, audited dependency metadata and original-domain tracking. Numerical testing can disprove a claim but never proves one. Uncertified premises, old status flags, unknown dependencies and dependency cycles remain unavailable as proof authority.
